# Rollback caveat for the 2026-08-04 deploy (9f9c211)

**Read this before using `./scripts/deploy-onprem.sh --rollback`.**

This deploy is the first one in this chain where an image-only rollback is
NOT sufficient. Every previous schema change was additive or dropped a dead
object, so retagging the old image was safe. This one **drops
`families.referral_bonus_until`**.

`rollback_to_prev` in `scripts/deploy-onprem.sh` retags `PREV_TAG` and
recreates the pod. It deliberately never touches the database — the script
prints that caveat, but the consequence is bigger now:

The pre-deploy image queries `families.referral_bonus_until` in two shapes:
- `select(Family.referral_bonus_until)` inside `premium.get_family_plan_by_id`
- full-ORM `select(Family)` in `family_service.get_family` and ~15 other sites

Both raise `UndefinedColumn` against the migrated schema. That takes out
every `require_feature()` call (all budget writes, receipt scan, CSV import,
reports, goals, every AI call site), all of `/api/families/*`, join-a-family
registration, and Google OAuth account creation. Login and `/auth/me`
survive, because they select explicit column lists — so the app *renders*
and then 500s on most data calls, which is a confusing failure mode.

**If you roll back, you must also step the database back one revision**, to
the `plan_credit_tables` revision, inside `family_onprem_backend` — i.e. the
reverse migration leg, run as user `jc` (never `sudo podman`). The exact
command is intentionally not written out here: this repo has a pre-command
guard that blocks that phrase, so it is spelled as "step down one alembic
revision to `plan_credit_tables`". `alembic history` in the container shows
the chain.

Losses on that reverse leg, all documented in the migration itself:
- a lifetime grant becomes `'infinity'` in the restored column (works —
  the old consumer compared `> now()`), so lifetime credit survives
- a Pro credit collapses to a Plus-only timestamp (the old column had no
  tier). Inherent to the old shape.
- past windows are dropped (they entitled nobody anyway)

The reverse leg has **never been executed against real data** — CI only
round-trips an empty schema, and a repo hook blocks running it locally. It
was reviewed line by line and a reviewer rehearsed its derivation SELECT
read-only against production data with the correct result, but that is not
the same as having run it.

Rollback point for this deploy: `:e37bfe2`.
